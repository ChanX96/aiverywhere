# extract · 提取

契约版本 1

## 职责与触发

出现用户纠正、新事实、可复用方法或值得追查的问题时调用。没有候选就返回零条，不为了写日志而制造记忆。

## 输入与输出

输入：本次任务的目标、证据、用户纠正和已有记忆。

输出：零条或多条候选；每条包含类型、标题、正文、来源、适用范围和已有记录引用（如有）。

## 做法

1. 把用户明确要求保存、设定默认值或纠正旧约定的内容列为必记候选。
2. 从已验证结果中提取可复用方法，写清适用条件、操作和验证依据。
3. 有证据但仍有明确下一步的问题写成 clue。
4. 区分项目 fact 与跨项目 skill；合并重复候选，纠正已有记录时保留原 ID 和 revision。
5. 一次性要求、闲聊和无持久价值的内容跳过。

## 示例

应触发：用户说“以后本项目月报默认用万元”。

可跳过：用户只说“这次用元”，没有要求长期默认。

## 失败处理

证据不足时降级为 clue 或丢弃候选，不要猜测用户偏好。无法判断是否共享时默认保留在当前项目。
