# aiverywhere 项目设计方案

**项目目标是用最简单的方式，实现一个高度自由、能力强的自主 agent。** 同一份工作约定可在宿主或独立 CLI 中使用。模型按需要探索、选工具、验证和学习，逐渐掌握更多编码、办公与日常任务。只有行动或交付确实需要的机制才进入内核。

首版设计于 2026-11-21，采用项目本地文件和可选 Python CLI。架构与工程文档集中在 `docs/`。面向使用者的 README、安装指南和使用手册同时提供中英文版本。开发者遵循[项目开发规范](development.md)，宿主、CLI 和后台共用同一个 [agent 定义](../../skills/aiverywhere/SKILL.md)。

## 已确认的方向

| 方面 | 已确认的需求 |
| --- | --- |
| 运行方式 | 宿主委派、当前对话接管、macOS / Linux 独立运行共享工作约定。先验证委派；安装与宿主导入不按产品分支，任何具备文件或命令能力的宿主使用同一路径。 |
| 模型与内核 | aiverywhere 是 LLM 之上的薄层。模型理解目标、判断需要哪些上下文、选择行动；内核提供上下文入口，执行获准的动作，并把结果交回模型。 |
| 极简与可迁移 | 用标准 Python 包结构组织代码，尽量少写代码、少建文件。能力来自工具、MCP 和按需加载的技能。项目自身产生的持久文件归可写安装目录。 |
| 学习与专注 | 从空白记忆开始。模型按当前任务决定是否回忆或查技能；能直接创作、从工作里主动求证和学习，也能重新发现闲置技能。记忆首选无外部依赖的方案。 |
| 跨项目复用 | 默认允许同一用户的不同项目复用经验证的通用方法。原项目保留具体事实和资料。用户要求事先确认的动作，必须在取得相应确认后才执行。 |
| 主动工作 | 支持宿主、浏览器和个人微信。由 aiverywhere 自己执行预授权的周期任务，包括宿主缺少定时能力的场景；能在任务之外主动反思（Dream）、验证经验和提出建议。 |
| 异常恢复 | 因关机、休眠或运行环境中断而错过的任务，在 aiverywhere 下次启动时提醒用户。是否补做由用户决定，后续周期依原计划执行。 |

宿主可直接读取工作约定。独立 CLI 和后台均可把一次任务交给已配置的原生执行器，也可使用裸 Anthropic Messages 端点。记忆使用本地 memory-v1 JSON 文件和日志，事实/技能默认检索会跳过 90 天未更新或未经验证复用的条目；线索不受冷过滤。当前已在 macOS 验证假微信回执恢复，Dream 已改为普通任务并由测试覆盖空线索零调用与线索处理；一次性 `wake` 由外部调度器调用；2026-11-22 在 macOS arm64、Python 3.9.6 和 3.14.2 上验证用户级安装的仅宿主、`--cli`、自定义安装根、重复安装保留数据和项目链接反向定位。真实个人微信、浏览器渠道、Linux 外部调度、真实交互 TTY 及分段记忆索引仍待验证。[运行说明](../../README.md)

## Skill、CLI 与后台调度各负责什么

| 职责 | 输入与可核验的输出 |
| --- | --- |
| **Skill 和执行它的模型** | 读取唯一的工作约定和本次目标，自行决定是否回忆、用什么工具、何时验证与沉淀技能。宿主已有执行工具、进度以及向原会话回投的能力时直接使用。普通问题直接给最终答复。 |
| **CLI** | 用 `init`、`setup`、`link` 准备实例、模型与运行参数并暴露活动 agent；绑定项目后传入工作约定和目标，顺序执行任务并控制超时、取消和结果归属。选择原生执行器时，每次提交启动一次用户指定的前台命令，以标准输入传任务，从标准输出收最终正文。执行器在用户选定的权限下完成全部中间步骤。 |
| **后台调度** | 由宿主或外部 cron/launchd/systemd timer 调用一次性 `wake`。认领到期任务，记录结果、核对渠道回执、恢复未完成的投递；有空闲且存在线索时触发一次普通 Dream 任务。长任务共用这次唤醒的工作进程，进度提醒最多一条。 |

**每项任务只有一个负责行动的 agentloop。** 宿主对话用宿主的循环。CLI 调用原生执行器时，循环随任务移到该执行器，它接收固定版本的工作约定和带角色的任务文本，自行管理工具和上下文。机器只有裸 Messages 端点时，使用项目内唯一的本地循环 `Messages.agentloop()`。它向模型提交目标，收到最终文本就退出，收到本地工具请求就执行获准动作并交回配对的 `tool_result`。模型决定行动顺序、是否回忆及何时完成。超时、取消、授权和回执由运行时执行。[Anthropic 客户端工具协议](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)

学会一个方法只需保存有适用条件和证据的技能正文。模型自行决定何时阅读、怎样用现有工具验证。比如把“月报核对公式坐标”保存成技能，宿主和 CLI 都可按线索取回并使用。验收比较同一项目、同版技能及授权下的实际产物和回执，允许模型选择不同的工具顺序。

实例的工作约定位于标准 bundle `<实例>/skills/aiverywhere/SKILL.md`；旧 `data/SKILL.md` 作为兼容回退。首次初始化优先采用实例原有内容，新的实例从发行模板开始。宿主通过 `skill --info` 取得活动路径及 SHA-256。影响全部任务的改进可在授权后按旧哈希原子发布。已在运行的任务按下述读取时机感知修订。用户偏好逐次确认时先展示建议并取得同意，工具权限始终由执行环境授予。

宿主读取该文件后，原生工具循环可以连续发现资料、验证方法、写入项目经验，直到取得结果或需要用户决定。宿主会话关闭后，接入时绑定的唤醒方负责启动新的工作。已有可验证的宿主调度器可自动调用 `wake --dream`。独立安装不写入系统注册文件，由使用者自己的 cron、launchd 或 systemd timer 周期调用一次性 `wake`。模型可用 `memory put --kind clue` 留下待验证问题，宿主或 `wake` 在空闲时触发一次 Dream；没有线索时模型调用为零。

## 只保留一个 agent 定义和一个 Python 入口

- 唯一维护的发行模板位于 `skills/aiverywhere/SKILL.md`。新实例从模板生成自己的活动文件。安装器通过 `aiverywhere link` 在项目 `.agents/skills/aiverywhere/SKILL.md` 建立指向活动文件的链接，不按宿主区分目录；其他宿主读取同一绝对路径。CLI、后台和本地工作台也使用它。[Agent Skills 规范](https://agentskills.io/specification)
- 首版使用 `src/aiverywhere/` 标准包布局。CLI、Dream、计划和渠道调用 `Task.run()`。只有裸 Messages 路径才构造本地工具、发现 MCP 并处理工具回合。原有 Python 调用名 `Task.agentloop()` 保留为兼容入口。
- 源码、给人看的 README 和包配置随安装提供。**除安装器显式创建的项目技能链接和命令链接外，所有 aiverywhere 自己产生的持久文件都写在可写安装目录内**。资料归属、日志、缓存、临时写入文件、学出的技能和定时任务都遵守同一条路径规则。工作对象可以是用户授权的其他仓库或文档，那里只写任务明确要求的产物。安装目录只读时直接报告，并支持只读会话；需要持久化的用户可将整包放在可写位置。更新程序保留安装内的数据目录。

核心壳只维护一份 `SKILL.md`、一个最小模型/工具循环、一个记忆与线索存储，以及宿主/CLI 入口。`web`、微信网关、`schedule`/`wake`、MCP 和原生执行器是可选适配器；它们可以存在，但不决定核心循环。CLI 的 `chat` 一次只推进一个前台任务，输入队列允许在运行期间接收 `/cancel`；`wake` 由外部调度器调用一次；Dream 是普通任务，空闲触发归宿主或外部调度器。

**工具。** 裸 Messages 的核心文件工具是 `list_files`、`read_file`、`search_files`、`write_file`、`edit_file`；`write_file`/`edit_file` 只在 `--allow-write` 下出现，局部编辑校验读取所得 SHA-256 和唯一匹配片段。`run_command(argv, cwd, timeout)` 只在 `--allow-exec` 下出现，返回退出码和限长输出；取消时终止进程组。`web_search` 使用免 Key 的 Bing RSS，失败时回退 DuckDuckGo HTML，`web_fetch` 只接受公开 HTTP(S) 文本页面，逐次校验重定向目标，拒绝内网、回环和保留地址。权限由运行时过滤工具，而不是只写在提示里。

**worker。** 主任务可调用 `delegate(tasks)`，首版最多 2 个、深度 1 层。每个 worker 是独立 `Task.run()`，有独立 ID 和对话历史，文件工具根指向 `work/<主任务>/<worker>/` 私有项目副本；真实项目、实例配置和其他 worker 不在其文件路径内。worker 交回摘要、证据和 artifact（ID、路径、大小、SHA-256），主任务核验后调用 `accept_artifact` 写入授权目标。命令只在 Seatbelt/bubblewrap 实际探测通过时开放；否则 worker 保留受限文件工具并报告命令不可用。父任务取消会级联取消 worker，单独的 `/cancel <worker-id>` 不影响兄弟任务。

**流式与取消。** Messages 适配器读取 SSE 文本增量；工具参数和回合结束信号完整后才执行工具。非 `--json` 的 `run`/`chat` 流式显示正文，完成时只显示一次；`--json` 保持单份最终回执。Ctrl+C、`/cancel` 和 worker 取消都走同一取消路径，已完成的原子写入保留回执，结果未知的外部操作标为待核对。

### 一句话安装与运行参数

发行包提供 POSIX `sh` 的 `install.sh`。默认实例根是 `<项目>/.aiverywhere`；默认只复制 skill bundle、创建记忆目录和项目链接，不需要 Python。`--cli` 才在实例根创建 `venv`、链接 `aiverywhere` 并运行 `setup`。用户级共享实例可用 `--home ~/.aiverywhere`。安装器不请求 `sudo`、不修改 shell 启动文件、不注册系统服务。

`setup` 依次询问模型服务、凭据方式、模型名、单次输出 token 和运行预算。除模型名和凭据外都有默认值，非交互模式可用参数或环境变量补齐。`model` 保存端点、模型、`max_tokens` 和凭据来源；`defaults` 保存 `max_turns`、`timeout`、`port`。凭据可写 `api_key`/`auth_token`，也可只写 `api_key_env`/`auth_token_env` 环境变量名。重复运行安装器保留 `data/`，`init` 不覆盖已有活动文件。

### 实例目录和本地工作台

源码仓库仍可作为实例根；项目本地 `.aiverywhere/` 是默认绑定，用户级共享实例使用 `~/.aiverywhere` 或 `--home`。CLI 通过项目 `.aiverywhere/instance.json`、项目 skill 链接或 `--home` 绑定。`--project` 仅选择任务的工作目录和记录范围。首次 `init` 准备下列活动文件，用户数据由 Git 和发行包排除。

| 位置 | 内容与访问方式 |
| --- | --- |
| `skills/aiverywhere/` | 标准 skill bundle：`SKILL.md`、references、Shell 脚本和 schema。宿主不需要 Python。 |
| `data/memory/<project_key>/` | 记忆 v1：一条记录一个 JSON 文件，ID 稳定，revision 递增。 |
| `config.json` | 唯一实例配置，分为 `model`、`defaults`、`mcpServers`、`wechat`。 |
| `data/state.json` | 计划、任务认领和渠道回执；不再保存记忆正文。 |
| `data/logs/` | 按任务保存的摘要和回执，避免共享追加文件。 |
| `data/artifacts/` | worker 或任务产物。 |
| `work/` | 可回收的 worker 私有工作区。 |
| `data/.lock` | CLI 所有进程共用的文件锁；Shell 宿主使用自己的原子/冲突回执。 |
| `data/artifacts/` | worker 交回并保留的产物；主任务核验后通过 `accept_artifact` 写入项目。 |
| `work/<主任务>/<worker>/` | 可回收的 worker 私有工作区；真实项目、配置和其他 worker 不在此范围。 |
| `venv/` | 安装器管理的运行环境，不属于用户数据。 |

`init` 在实例锁内把旧版 `data/config.json` 原子迁移到实例根 `config.json`；新旧配置同时存在且内容不同时报冲突，不静默覆盖。`config.json`、`data/` 和 `skills/aiverywhere/` 一起备份即可带走实例。

项目技能链接位于 `<项目>/.agents/skills/aiverywhere`，指向标准 skill bundle 目录；旧 `SKILL.md` 文件链接可迁移。它只是宿主导入路径，也可用于从项目反向定位自定义安装根。`web` 用 Python 标准库在 IPv4 回环地址提供本地工作台。操作员可在“对话与工作”提交任务、查看工具回执，检索和编辑当前项目的记忆与技能、查看和修订实例级 agent、分页浏览当前项目的日志。对话会话保存在当前 web 进程内，后端线程执行任务，前端轮询状态；默认只读，写入、命令和联网分别由 Task 权限字段控制。删除条目需确认，写入和删除核对当前修订。删除本地 agent 修订后可以从模板恢复。配置可能包含凭据，只通过本机文件配置。页面按资源提供操作，避免直接改写含有任务状态的整个快照。浏览器对话与微信渠道分别验收。

### 运行中的文件变更

| 读取方 | 何时看到变更 |
| --- | --- |
| 裸 Messages agentloop | 每次发出模型请求前读取活动 agent，把修订放入当轮上下文。工具回合之间修改文件，下一轮用新内容。已提交的调用按原有权限和回执完成。 |
| 宿主和原生执行器 | 每次新委派传入当前定义。宿主在长任务的行动阶段交界、上下文恢复等检查点自行核对活动路径与修订。原生命令若只接收一次标准输入，进程中的感知依赖它主动重读。 |
| 记忆、技能和线索 | 检索和按 ID 取回时使用现行状态。裸模型回合只核对本任务用过的条目。快照变动后，已修改的条目以 ID 和新修订提示，删除或失去访问权的标为不可用。该范围为空时无需为此读取记忆。 |
| 配置 | 交互 CLI 在任务或追问从队列实际启动时读取执行器配置，正在执行的调用维持原绑定。计划和 Dream 每次执行重新取配置，微信发送时核对原会话绑定。MCP 在下一次建立连接时取当前配置。 |
| 本地工作台 | 前台标签页每 3 秒用条件请求检查文件版本，切回标签页立即检查。有变化才重新读取内容。对话在进程内保留上下文并轮询任务状态；默认只读，工作模式需显式开启。并发编辑保留本地草稿，用修订冲突避免覆盖他人。 |

这些检查复用已有的模型回合、子命令、调度器和本地网页。空闲时没有为文件变化调用模型，也无需安装文件监控服务。

同机并行进程用实例内同一把文件锁更新状态，锁内读最新修订，写临时文件并原子替换。`state.json` 仍是一份有效的 v1 JSON。首行保存计划、任务、提醒及有待反思的项目，调度器检查一次即可跳过记忆正文。旧布局按完整 JSON 读取，下次写入采用新布局。查记忆和提交修改仍需读完整状态，任务记录增长也会增加首行的开销。分段索引是否值得引入由后面的对照实验决定。

### 候选方案：用本地文档做追加写入与定点检索

Iceberg 的快照记录一批可见数据文件，清单中的分区摘要等信息可以帮助读者跳过无关文件，切换元数据时原子发布。Kafka 在分区内给记录分配逻辑偏移量，用段内索引定位物理文件位置，并能按键压实旧值。aiverywhere 可以借用这两个思想，由单机文件锁和标准库实现。逻辑序号用于排序和续读，字节位置只对特定文件段有效。[Iceberg 表格式规范](https://iceberg.apache.org/spec/) · [Kafka 日志设计](https://kafka.apache.org/42/design/design/) · [Kafka 的偏移量索引实现](https://github.com/apache/kafka/blob/4.1.0/storage/src/main/java/org/apache/kafka/storage/internals/log/OffsetIndex.java)

**从双文件起步。** 这个候选方案把知识正文的权威记录移入追加日志，一开始只有一个以起始序号命名的段，如 `data/events-000001.jsonl`。`data/state.json` 继续保存任务、计划和确认偏好，并保存记忆索引快照及段清单。每次写入追加一条记录，快照可攒一批再更新。条目和主题共用这些文件，达到轮转条件后再增加文件段。两种布局是备选，选定后只维护一套正文。

| 操作 | 用普通文件怎样完成 |
| --- | --- |
| 写入或纠正 | 在同一把写锁内，用稳定请求 ID 去重，核对条目修订号，为本次变更分配递增事件序号。将条目 ID、用户与范围、类型、操作、线索、正文或证据引用编码为一行 UTF-8 JSON。可持久化的成功回执在完整追加并同步落盘后返回。 |
| 查找“这个项目的月报” | 先限定用户和项目，再用“月报”及获准别名查候选 ID。快照保存简短摘要、当前修订、冷热状态及正文定位信息（段 ID、字节位置、字节数）。合并快照之后的日志尾部，排除旧版和已删除项；模型先收到少量摘要，选择展开时才按字节定位正文。文件放在同一目录不代表可以跨范围读取。 |
| 冷启动及模糊查询 | 新进程读紧凑快照和未索引的日志尾部，常驻进程复用内存索引并检查新序号。无精确匹配时，可在授权范围内分页匹配短摘要的中文子串或换线索。需要扫描历史时，用段清单的范围、类型和时间摘要排除肯定无关的段。索引解决定位成本，同义问法的召回率单独衡量。 |
| 断电与并发 | 快照记录所纳入的最后序号，在同目录写临时文件并原子发布。追加已落盘而快照尚旧时，按序重放尾部。末尾半行在写锁内核实并修复；中部损坏报告具体段和位置。缓存索引可从已发布清单中的段重建，任务和授权状态继续独立保存在状态文件中。 |
| 删除与压实 | 用户删除时先追加删除记录，使直接读取、热缓存及深搜都看不到该条目。压实时将有效记录及仍需保留的任务证据写入新段，验证并落盘后原子切换清单，再在没有旧读者时移除旧段。明确删除的正文及其受控日志副本优先清理；完成清理前分别记录“已隐藏”和“已清除”。物理位置可变，供技能和线索引用的条目 ID、事件序号保持稳定。 |

**定点读取的字节数可以先算清。** 设计阶段用标准库在内存中构造了 100 个项目、每项目 100 条记录；每条正文是“导出后核对公式位置与数量。”重复八次。按“项目＋唯一主题”查询一条，紧凑 JSON 全集为 3,668,891 字节；仅含键、偏移和长度的索引为 286,966 字节，已知位置后读取该条 JSONL 为 367 字节。此例首次查找要读 287,333 字节。真实索引还要容纳范围、修订、摘要和日志尾部，常驻的基线同样可以缓存；这些数字只说明为什么定点读取值得验证。

**选型在记忆阶段验收。** 让两种布局运行同一批 100、1,000、10,000 条合成数据，测精确命中、两字短词、同义改写、无结果、热门条目反复修改和删除。分别记录冷／热查询 p95、读取与写入字节、占用空间、索引重建时间和前三项召回率。只有在目标负载下收益可复现，且中断恢复、范围隔离和删除均通过时，才选用分段与快照；否则保留简单双文件基线。

## 让 agent 自己决定什么时候回忆

模型在原本就要进行的首轮推理中决定直接作答、查记忆或找技能，执行中获得新线索时可以改选。初始提示包含当前任务、必要的近期对话和少量基础工具定义。项目经验及技能目录按需查找，临时任务可以全程零检索、零额外分类模型调用。权限、用户本次明确要求和已经声明的执行约束始终有效。

| 用户当前要做什么 | agent 可以怎样判断 | 怎样验证 |
| --- | --- | --- |
| “给这个新产品想三个出人意料的名字，随意发挥” | 当前信息足以创作，可直接作答。即使库中有同类项目的旧名字，也没有理由先读。 | 加入大量旧案例后，首轮仍可零检索；答案和提示里不泄入测试用旧名。 |
| “这次也沿用上次给客户的命名风格” | 当前请求明确依赖过去。先在这个项目里查“客户、命名风格”，取少量摘要，证据足够就停止。 | 找回带出处的偏好；未找到时说明不确定。 |
| “把这份月报排好版” | 目标涉及已有文件，可能存在项目约定。可以先查当前项目相关约束；若还缺操作方法，再查技能。 | 找到“在副本上编辑”的本项目约定。另一个项目的版式不能混入。 |
| 自己尝试处理一个新格式，第一次导出失败 | 开始时可自由探索。出现具体错误后，用错误信息和文件类型找旧办法，必要时扩大到冷技能。 | 能在执行中途切换路径。一次失败不会让所有后续任务都加载该技能。 |

检索入参概念上只有线索、允许的范围、想找的类型、预算和是否含冷记录。先查当前范围的主题、别名和摘要，中文两字词也可直接匹配，再读少量选中的记录。范围由可信入口绑定。没有命中时可换线索或显式扩大到已授权范围。被展示不计入熟练度；确实复用并验证才更新使用记录。长期未用的条目退出默认结果，明确查询仍可找回。用户纠正时保留适用条件和替代关系，要求删除时清理有效数据、派生缓存及本项目可控日志中的相关内容。

## 做中学，也能主动行动

例如，A 项目的月报导出时丢了公式。用虚构表格复现并验证后，agent 可将“导出前后核对公式数量”提炼为该用户的通用技能。B 项目可按需找到方法和通用样例。A 的客户名、原表、路径及项目约定只在 A 可见。

确认偏好按用户表达的范围生效。若用户说“跨项目使用技能时先问我”，执行入口要在向 B 提供技能内容或用它行动之前取得确认；若用户要求在共享时确认，就在写入共用范围前询问。本次同意只覆盖用户同意的范围。这个检查发生在相关动作的边界，无需依赖模型碰巧想起该偏好，也无需给每轮闲聊加载偏好清单。无人值守的任务遇到需要确认的动作时保留进度，等用户回复。

1. **在任务里学。** 用户明确交代的持久偏好立即保存。遇到意外、修正或成功复用时，模型根据本次证据判断是否值得留下。普通寒暄和一次性灵感可直接结束。新安装从空状态开始。
2. **把经验变成技能。** 一次成功可留下“待验证”的办法。遇到相似任务，或能在获准的本地样例上复现时再验证。成功后保存可用版本、条件及样例，供后续任务发现。已经执行的行动使用当时的版本，后续阶段可再次取回当前修订。模型可以提出或整理技能，工具权限继续由运行环境授予。
3. **主动补齐缺口。** 在已授权的目标和预算内，agent 可主动查资料、试一个可逆样例或安排一次复核。例如一次导出失败后，比较两种获准工具的结果，将能复现的办法留下。超出当前目标的事项向用户提议。没有待验证的问题时，空闲无需调用模型。

### Dream 如何产生新认识

前台的“潜意识”决定眼前这一步要不要查经验。Dream 处理另一个问题：几次已经结束的工作放在一起，有没有值得重新验证的想法？aiverywhere 不为 Dream 维护专用循环、JSON 契约或租约：线索是普通记忆条目 `kind=clue`，Dream 只是一次普通 `Task.run()`。宿主在空闲时用自己的模型执行；CLI 用同一提示词；`wake --dream` 只负责触发一次。

例如，两份周报都通过了“导出前后公式数量相同”的检查，其中一份仍被用户纠正。Dream 可以提出假设：公式数量相同，位置也可能错了。它可以在获准的本地范围做一个最小实验，移动一条公式但保持总数，再比较旧方法与逐格核对的结果。能够复现才修订原技能，保留依据与适用条件；证据不足就留下待验证的问题。这样一次反思能改进下一次工作。

- **何时想。** 模型在任务中用 `memory put --kind clue` 留下用户纠正、反复失败、矛盾结果或待验证想法。宿主在用户任务结束且暂无新请求、或下一次会话开始时检查 `memory search --kind clue`；CLI 可用显式 `dream`，或由外部调度器调用 `wake --dream`。没有线索时直接结束，本次模型调用为零。
- **想到哪里。** 只取当前项目未处理的线索，先用摘要选择，再按 ID 取正文。模型可以用只读工具核实，也可以做获准的可逆实验，或得出“维持现状”。证据足够才写 fact/skill 并用 `memory forget` 标记已处理；证据不足就保留线索。
- **怎样停。** 为本次 Dream 限定小预算，临近前台任务或约定交付时让出执行机会。没有专用租约，重复触发可能重复思考，但锁和修订号保证状态一致；Dream 自己写记忆不会再隐式产生线索，因此不会自我循环。外部行动及技能跨项目复用沿用用户的确认偏好。

### 定时任务如何准时启动并交付

以“每周一九点整理周报”为例。创建时存下时区、授权资料、产物、交付渠道和预算。“九点开始”与“九点前收到成品”是两种约定；后者需要安排更早开工，分别记录计划时刻、实际开始、产物完成和渠道送达时间。

**唤醒方只需调用安装目录内的 aiverywhere 入口。** 入口认领到期任务，读取计划、加载项目上下文，驱动获准的模型和工具整理周报。产出后核实报告位置、所属周期和来源，保存任务 ID、产物引用与执行回执，再交付到指定渠道。这样用户能追查某期报告确实由哪个运行实例完成。

| 环境 | 选择和能力边界 |
| --- | --- |
| 宿主能定时且能独立调用入口 | 先在关闭交互会话的条件下验证一次短延时唤醒。能拿到 aiverywhere 的执行回执，再把它选作该计划的唤醒方。只能发提醒的宿主继续探测系统能力。 |
| macOS 或有 systemd 的 Linux | aiverywhere 不登记系统服务；由用户自己的 cron、launchd 或 systemd timer 周期调用一次性 `wake`。计划和时区保存在实例内。macOS 依赖用户登录会话，Linux 依赖可用的用户管理器。离线错过的事项在下次启动时核对。 |
| 宿主和系统都没有可用调度 | 若可保持进程运行，同一个 Python 入口进入等待模式，睡到最近的到期时间；新增或修改计划时重算。由已有进程管理器托管时验证其重启行为。仅能在对话期间执行的沙箱把计划标为“等待可用执行环境”，下次启动时提醒用户期间错过的任务。 |

登记计划时还须验证后台身份能读取指定资料、使用模型端点、写入产物。只在前台宿主会话里可用的模型，不能作为独立后台任务的已验证依赖。每份计划选一个主要唤醒方；计划查询显示其可用状态、下次应执行时间、最近回执和未交付原因。

每期用“计划 ID + 应执行时刻”标识。在同一状态文件锁内认领，重复唤醒沿用该期进度。网络或模型暂时不可用时，在本期时限内有限重试。进程中断后先核对产物和回执；仍在交付时限内且已生成报告时，从交付步骤继续。发送结果未知时先查渠道回执，或使用渠道的幂等能力；无法核实就保留“送达待确认”。

### 下次启动时怎样提醒

aiverywhere 启动或从休眠恢复时，按当前用户核对上次检查以来的计划时刻和已有回执。正常到点的任务照常执行；离线期间已经错过的任务记为待提醒。系统延迟送来的定时信号也走这次核对，只有用户要求补做才启动当期工作。已经开始的任务按已知进度说明，例如“周报已生成，送达待核实”。

有遗漏时，在当前会话简短提醒，例如“周一 9 点的周报错过了。下次仍是下周一 9 点；这期需要的话可以补做。” 多期遗漏可以合并。后台先启动时，把提醒保留到该用户下一次打开会话；已展示的事项在再次启动时保持安静。没有遗漏就直接进入当前任务。核对使用已有计划和运行状态，无需读取历史对话或调用模型。

## 独立运行、宿主委派和日常入口

### 在第一轮辨认环境

独立 CLI 与宿主委派共用一个有界的只读探测。读取系统、架构、Python 版本、入口、是否为交互终端、绑定的项目和实例根目录。只检查项目根的一小组标志文件以及 PATH 上几个常用命令。结果随首轮模型请求进入上下文，用户也可以通过 `aiverywhere env` 查看。该过程无需模型调用、联网、启动子进程或写入实例状态。

例如在独立终端执行 `aiverywhere env`，`execution` 为 `local_process`。由宿主显式传 `--host <名称>` 或设置 `AIVERYWHERE_HOST` 时为 `host_worker`，`host.source` 分别为 `declared` 和 `environment`。只有单一已知宿主标记时，`source` 为 `hint`。标记冲突或缺失时分别为 `ambiguous` 和 `unknown`。只记录标记是否存在。两种入口绑定同一项目时看见相同的项目事实，本次允许写文件、使用哪些 MCP 服务则取决于调用方传入的授权。

环境信息分别标明观察结果、本任务授权和未验证能力。比如发现 `launchctl` 只说明可找到命令，实际唤醒须另做验证。纯 skill 模式复用宿主已给出的身份和可用工具，缺少的信息保留未知；需要了解本地工作区且能执行命令时才调用环境入口。模型查更深层信息时仍受当前任务范围约束。

2026-11-21 在 macOS arm64、Python 3.14.2 上验收。十次各启一个 Python 进程执行 `env`，含进程启动的耗时中位数约 56 毫秒，实例目录产生零个文件。关闭第三方包加载后也能完成探测。从当前宿主会话委派的 worker 与独立 CLI 均通过本机模拟的 Messages 端点核对了首轮环境字段，委派任务还实际调用了获准的 stdio MCP 工具。

### 运行入口

**宿主模式默认按需运行。** 宿主模型或原生子 agent 可以直接按 `SKILL.md` 工作。一次只用宿主能力的对话，可以全程零个 aiverywhere Python 进程。需要本项目的文件记忆接口时，可临时启动本地命令，返回结果后退出；委派给独立 worker 时，进程只持续到本次任务交回结果。需要保留的状态写入安装目录，供下次调用读取。

关闭对话后，周期任务或需要自动执行的 Dream 需要宿主或系统到点唤醒一个具备所需资料、工具和模型访问权的执行者。宿主也可以在自己的空闲检查点直接用当前模型做一次 Dream；没有执行者时线索保留，按下次启动提醒的约定处理。

| 入口 | 由谁推动对话 | 首轮要验证什么 |
| --- | --- | --- |
| macOS / Linux 独立运行 | CLI 把工作交给实例配置的原生执行器或 Anthropic Messages 端点。 | 原生任务验证最终文本、退出码和任务归属。裸端点验证一轮多个工具请求与回执按 ID 配对，以及取消和部分失败。[Anthropic 工具协议](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use) |

### 长任务的进度和原会话交付

优先使用宿主自带的“回复当前会话”和回执查询。若现有网关只提供收发 API，可信入口先把账号、会话、入站消息 ID 和原始目标写入实例，再确认接收。重复入站复用同一任务。模型交回正文，调度器从持久记录取原地址。生成完成先落盘，随后才发送，收件地址独立于任何对话摘要。生成中断且已有行动的结果不明时，向原会话返回中断说明，保留核对依据。

短任务直接交付。长任务出现有依据的偏差时，发一句需要核对的差异；长时间缺少检查点时，只报告经过的时间和当前状态。每个微信任务至多发一条这样的提醒，提醒与最终答复各有独立的发送 ID。模型根据最初目标和证据判断语义偏离。在裸 Messages 的下一次可用回合可提醒模型复核。只暴露最终文本的原生执行器在宿主内自行复核，后台只能观察耗时和最终退出。进度查询直接读本项目的任务记录，空闲监控无需轮询模型。

渠道接受、渠道确认送达和用户实际阅读是三个不同事件。发送后丢失回执时优先按稳定 ID 查询。有幂等保证的网关可安全重试。缺少两种能力时保留“送达待核对”。目前的适配约定服务于一个项目绑定的一个会话，个人微信登录、接收入站及平台送达证明仍由实际渠道提供。

2026-11-21 在临时实例上验证了两条路径。当前宿主读同一 skill 和两份合成资料，算出净额 42 元，通过标准输出交回正文，项目侧模型请求数为零。另一条路径使用模拟 Messages，工具对话压缩两次，假网关收下最终答复后断开连接，再杀掉调度进程。早期版本用临时 macOS LaunchAgent 自动拉起进程，查回受理和送达两个回执，原会话只收到一条偏差提醒和一次最终发送。同次运行中，到期计划执行一次。实验结束后已卸载临时服务。

### 用户环境的边界

源码或专用虚拟环境内可以直接运行，使用共享 Python 时显式选择 `--home`。默认启动、读取 skill、查看环境以及 `wake` 均不注册系统服务。安装器只在用户选择的安装根写入虚拟环境、`config.json`、`data/` 和可回收的 `work/`，并可选创建一个 `~/.local/bin` 命令链接和一个项目技能链接；不请求 `sudo`，不修改 shell 启动文件，不写入 cron、launchd 或 systemd 注册文件。已有宿主可按路径读取文件，用户无需全局安装 skill。外部调度器由用户自行管理；后台运行所需的凭据及宿主自身的缓存、日志与权限由该宿主配置管理。

### 稳定内核与数据驱动能力

内核只保留四类稳定机制：一次任务循环、受版本约束的工具协议、可校验的记忆格式，以及可恢复的 session/journal。能力优先通过数据扩展：

| 能力层 | 扩展方式 | 内核发版 |
| --- | --- | --- |
| 行为 | `SKILL.md` 和 references | 不需要 |
| 经验 | memory 的 fact/skill/clue | 不需要 |
| 外部系统 | MCP server 和配置 | 通常不需要 |
| 网络/文件 | 通用 web/file 工具 | 不需要 |
| 新原语 | 新工具类型、新事件格式、权限模型 | 需要且应低频 |

不把某个 App 的页面、接口或流程写进内核。某个 App 的用法先用 skill + `web_search`/`web_fetch` 表达；需要长期复用时写成 memory skill；需要专用协议时接 MCP。只有改变内核原语才发新版本。

### 权限边界与 session 授权

计划属于 skill，授权属于 CLI。模型可以在回复中请求权限，但不能给自己签发权限；`/grant` 和 `/revoke` 只从用户输入进入 CLI，并写入 session 的 `permission` 审计事件。

- 默认只读；`--allow-write`、`--allow-exec` 是启动时授权；
- `/grant write|exec|network` 和 `/revoke ...` 只影响当前 session，退出即失效；
- `--ask-permissions` 下写文件、编辑、命令和 artifact 写入逐次等待 `/approve` 或 `/deny`；
- 权限变化在两次任务之间重建 Task/Tools，保留同一 session、历史和 task_id；
- Web 工作台使用相同的 Task 权限字段，分别控制写入、命令和联网；
- 模型不能调用 `/grant`，也不能把授权写入 memory。

### CLI session 与自动 compaction

CLI 的交互会话按项目存放在 `<实例>/data/sessions/<project_key>/<session_id>.jsonl`。session 文件第一行是 `schema=1` 的头，之后是带递增 `seq` 的 `turn_start`、`turn`、`turn_error` 和 `summary` 事件。原始回合不被重写；`summary` 只改变下一次模型请求使用的上下文视图。

写入规则：

- 同一 session 由一个进程持有 `flock` 排他锁；
- 每个事件完整写入并 `fsync` 后才推进内存序号；
- 崩溃留下不完整尾行时，恢复从最后一个完整事件开始，下一次写入先截断残缺尾部；
- `turn_start` 没有配对的 `turn`/`turn_error` 时，恢复后标记 `result_unknown`，不把中断的工具调用当成成功；
- 文件权限 0600，目录 0700；session 正文可能含用户资料，不进入 Git。

默认 `aiverywhere` 恢复当前项目最近 session；`--new` 或 `/new` 开始新会话，`/resume <id>` 恢复指定会话，`/sessions` 列出，`/status` 显示 turn 数、估算 token 和摘要状态，`/compact` 手动压实。

`ContextManager` 在每次模型请求前估算 system、消息和工具定义的 token。超过 `session.compact_at * session.max_context_tokens` 时，保留最近完整回合，把更早的回合交给同一模型做无工具摘要；摘要请求失败或端点不支持时使用确定性摘要；压缩后仍超过 `max_context_tokens` 则明确失败。摘要事件记录 `method`、`covers_messages` 和创建时间；原始 session 不删除，摘要不是事实来源。

默认配置：

```json
{
  "session": {
    "max_context_tokens": 64000,
    "compact_at": 0.8,
    "keep_recent_turns": 6,
    "summary_max_chars": 4000
  }
}
```

第一版不自动删除旧 session；用户可用 `/sessions` 查看并显式清理。

### CLI 如何顺序处理输入

交互式 TTY 使用顺序 prompt：一次只推进一个前台回合，结束后重新显示 `aiverywhere ›`；运行中按 Ctrl+C 取消，逐次权限审批在同一 prompt 中显示。非 TTY/管道输入仍使用输入队列，可在运行中发送 `/cancel`。连续输入共享同一个 session 和 Task 历史；只有 `/new` 或 `--new` 切换 session。`/ask` 用于向当前 session 的已完成任务追问，`/jobs` 查看最近状态。并行只发生在主任务内部的深度 1 worker；这与宿主当前会话的“一次推进一个回合”保持一致。

需要并行推进独立任务时，使用多个终端、多个宿主 subagent 或分别调用 `run`；不同进程仍用同一把实例文件锁和修订号保护状态。验收时提交两行任务，确认它们按顺序完成且输出归属正确；在任务运行中关闭进程，确认已发起的动作保留可核对的回执。
### 两种环境怎样交接一个任务

发起方提供稳定的任务 ID、目标、完成条件、授权的项目范围和预算。被委派方独立推进，向原入口交回状态、结果和可核对的证据。遇到只有用户才能决定的问题时，连同已完成的部分交回，由原会话承接答复。同一任务由一个模型循环驱动。

不同入口或进程可以并行；同一会话内需要前序结果的动作依次执行。收到取消时，停止派发新动作并汇总已经发生的结果。渠道重复投递时按消息身份识别原任务；外部写入结果未知时先查询回执，再决定是否重试。两种环境的验收比较这些可观察行为，允许模型选择不同的步骤。

## 开发顺序和验收

1. **先证明内核可带走。** 从当时可用的宿主委派一项代码任务，独立入口跑同一例。比较完成条件、证据、授权和取消结果。宿主直接作答时验证无项目 Python 进程启动；用两次独立的临时命令写入和找回同一条记忆，验证进程退出后仍可复用。真实端点完成一次工具往返，模拟端点覆盖并行和失败。
2. **再证明会记也会放下。** 使用合成资料，成对测试“自由创作 / 沿用旧风格”“首次出现 / 曾经纠正”。记录无关任务误检索率、需要经验却漏检的比例、前三项命中、额外模型轮数及注入 token。在 100、1,000、10,000 条记录下分别测新进程首查与常驻查询，比较耗时、字节数及并发写入。未实测前，文件与数据库的效率保持为待验证假设。
3. **走完学习和日程。** 用同一个月报样例验收两次。默认设置下，B 可复用 A 验证过的方法，结果里只出现 B 的数据；用户设为“每次先问”后，B 的相关动作等待确认，拒绝则跳过。写入一条 clue，让宿主用自己的模型处理一次，检查能否改进技能、标记线索完成；空线索时检查模型调用为零，重复唤醒检查是否只产生可接受的工作。CLI 用同一提示词跑一次并核对线索和记忆状态。关闭宿主并禁用其调度能力，用系统或受托管的入口真正完成一次短延时报告；记录约定允许的偏差与实际延迟，检查执行者回执和产物。模拟关机错过一期周报，确认下次会话展示一次提醒、当期执行次数为零、下一期仍按时运行。另测后台先启动、重复唤醒及“报告已生成、送达未确认”，核对提醒与真实进度一致。
4. **再接个人入口。** 验证真实浏览器和个人微信对话、回执、身份隔离和消息送达。在可写安装目录部署、迁移、升级后核对记忆、技能、计划和日志均在目录内。

上述场景按改动范围进入开发和评审；工程结构、依赖管理、测试命令与交付证据见[项目开发规范](development.md)。
